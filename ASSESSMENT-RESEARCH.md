# Почему такой проект подходит для портфолио

Исследована небольшая качественная выборка публичных заданий и одного учебного challenge. Это не статистика рынка, поэтому по ней нельзя утверждать, что определённый процент компаний требует конкретную функцию. Требования зависят от уровня позиции и компании; некоторые примеры используют более старые инструменты.

## Что встречается в примерах

| Пример | Что проверяют | Что использовано в Dispatch |
| --- | --- | --- |
| Avtocod: Frontend developer test task | SPA, маршруты, store, создание/удаление отчётов, сохранение после перезагрузки, валидация, README; как плюсы — тесты и адаптивность | Vue Router, Pinia, CRUD, localStorage, валидация, тесты и инструкции |
| Wallstreetdocs: Task Analytics Dashboard | Vue 3, Composition API, Pinia, фильтрация, пагинация, аналитика; также полноценный backend и real-time | Клиентская часть с фильтрами, пагинацией и вычисляемыми показателями; backend и WebSocket не заявляются |
| SoWell: Senior Front-End Aptitude Test | Отдельный компонент загрузки файлов, понятный код, работа с props/emits, E2E-сценарии и способность объяснить решение | Переиспользуемые Vue-компоненты, props/emits, контролируемые формы, тестируемые доменные функции; загрузчик и E2E не реализованы |
| Frontend Mentor: Product list with cart | Состояние корзины и согласованное обновление интерфейса | Общий принцип одного источника данных: таблица, карточка и аналитика обновляются из Pinia |

## Вывод для этого портфолио

Первый проект FORMA демонстрирует визуальную вёрстку и небольшие интерактивные элементы. Второй проект дополняет его работой с данными и прикладными сценариями. Логистика выбрана потому, что знакомая предметная область помогает объяснять поля, статусы и решения на собеседовании.

Увеличивать число страниц само по себе недостаточно. Полезнее показать завершённый путь: создание записи → проверка данных → изменение статуса → пересчёт показателей → сохранение после перезагрузки → экспорт. Именно этот путь реализован в Dispatch.

## Что можно показать на собеседовании

- Почему общее состояние находится в Pinia, а открытый диалог и текущая страница таблицы — локально.
- Как объединяются фильтры и почему сортировка не изменяет исходный массив.
- Как валидируются данные перед записью, а не только в HTML-полях.
- Как восстанавливается интерфейс после ошибки и что происходит при недоступном localStorage.
- Почему сумма стоимости грузов не названа выручкой.
- Какие проверки автоматизированы и где остаётся необходимость браузерного тестирования.
- Как заменить локальное хранилище на HTTP API и где потребуется серверная валидация.

## Ограничения и следующий разумный этап

Нет реального API, входа в аккаунт, совместной работы и live tracking. Это явно обозначено в интерфейсе и README. Для следующего этапа полезнее добавить настоящий API и браузерные тесты основных сценариев, чем ещё несколько декоративных страниц. Приложение не следует представлять как промышленную систему или как самостоятельно выполненное работодателю тестовое, если условия запрещают помощь ИИ.
